# SF2e Tactical Starship Combat

[English](README.md) · [Руководство](docs/guide-ru.md) · [Релизы](https://github.com/Huxtuntios/sf2e-tactical-starship-combat/releases) · [Сообщить об ошибке](https://github.com/Huxtuntios/sf2e-tactical-starship-combat/issues)

Модуль тактического космического боя для **Starfinder Second Edition** в **Foundry VTT 14**: корабли игроков и НИП, боевые станции, экипаж, опасности и отдельная зональная сенсорная карта.

Каждый персонаж сохраняет собственную инициативу и обычные действия. По умолчанию корабль игроков не получает отдельного хода; для корабля с критическим повреждением предусмотрено исключение ради проверки целостности корпуса.

> **Экспериментальный проект, разработанный с помощью ИИ.** Есть автоматические тесты и локальные проверки интерфейса, но полный сценарий работы в живом Foundry ещё не проверен. Сделайте резервную копию мира и сначала проверьте модуль на копии. Файлы системы не изменяются.

## Установка

В **Add-on Modules → Install Module** вставьте ссылку на manifest:

```text
https://github.com/Huxtuntios/sf2e-tactical-starship-combat/releases/latest/download/module.json
```

Эта ссылка заработает после публикации обычного релиза, не помеченного как prerelease. Для конкретного выпуска или первого предварительного релиза используйте:

```text
https://github.com/Huxtuntios/sf2e-tactical-starship-combat/releases/download/v0.14.0/module.json
```

Включите модуль в мире SF2e. Руководство есть в компендиуме **Guide / Руководство**.

При ручной установке создайте папку `Data/modules/sf2e-tactical-starship-combat/` и распакуйте **`module.zip` внутрь неё**. Файл `module.json` должен лежать непосредственно в этой папке. Автоматические архивы GitHub **Source code** предназначены для разработки, а не установки в Foundry.

Идентификатор модуля не меняется: `sf2e-tactical-starship-combat`.

## Быстрый старт

1. Создайте корабль игроков через **Starship Builder** либо преобразуйте актёра `vehicle` через контекстное меню. Обычные транспортные средства автоматически не преобразуются.
2. Импортируйте корабли НИП и опасности из браузера контента или компендиумов.
3. Перетащите персонажей на вкладку **Станции**, назначьте экипаж и посты.
4. Запустите мастер **Start Tactical Starship Combat**: корабли, экипаж, статусы обнаружения, опасности и объекты.
5. Бросьте инициативу как обычно. Действия доступны на сенсорной карте, во вкладке **Станции** и в отдельном окне **Действия станций**.

## Возможности

- **Две карты в одном бою:** обычная сцена корабля и отдельная зональная сенсорная карта с дальностью, курсом, областями и обнаружением.
- **Станции и экипаж:** пульт пилота, генератор, орудийная станция, сканеры, магический канал, пульт дронов и пользовательские станции. Отдельный менеджер показывает назначения и готовность.
- **Действия станций:** данные хранятся отдельно от интерфейса, проверки используют штатные средства SF2e. По умолчанию нарушения правил вызывают предупреждение; можно включить строгий режим. Неподдерживаемые способности остаются для ручного решения.
- **Корабельный урон:** щиты, корпус, иммунитеты, сопротивления, уязвимости, критическое повреждение, разрушение и целостность корпуса. Для учёта щитов используйте инструменты модуля, а не системные кнопки применения урона.
- **Опасности:** простые срабатывания и сложные рутины, ручные подтверждения ведущего или автоматический режим. Автоматизируются только поддерживаемые форматы правил.
- **Контент:** 74 корабля, 32 опасности, 37 действий, 17 орудий, 34 записи улучшений и три рамы; компендиумы на английском и русском. Для улучшений проверяются совместимость и вместимость станций, но не все их эффекты автоматизированы.
- **Оформление сенсорной карты:** светлая/тёмная тема, цвета текста, арты и символы, отдельные изображения объектов и фон с прозрачностью, обесцвечиванием и размытием. Неопознанные контакты не раскрывают свои арты.
- **Темы окон:** листы кораблей, действия станций, предметы-действия модуля и менеджер экипажа используют общую клиентскую настройку. У других игроков и у сенсорной карты тема не меняется.
- **Длительность эффектов:** начало/конец определённого хода, несколько раундов, ручное подтверждение условия и напоминания о поддержании. Уклонение показывает потраченные действия; поддержание не тратит действия автоматически.
- **История и ограниченная отмена:** до 80 записей изменений модуля, видимых ведущему, с причиной, изменениями корпуса/щитов и переходами к объектам. Отменяется только ограниченный совместимый набор изменений, но не броски, затраты действий или раскрытая информация.
- **Интерактивные описания:** состояния отправляются в чат и перетаскиваются на персонажей с сохранением степени; урон бросается с нужным типом, без автоматического применения. Контекстные КС используют характеристики оператора, когда это однозначно следует из правил; отсутствующие и неоднозначные КС остаются для ручного выбора.
- **Удобство:** запоминание размеров окон и вкладок на клиенте, поиск по справочникам, улучшениям и истории.
- **Сетевая работа:** изменения проверяет и сохраняет активный ведущий; права на корабль и станцию перепроверяются. `socketlib` не нужен.
- **Признак `starship`:** хранится и отображается на английском независимо от языка интерфейса.

## Ограничения

Полный многопользовательский сценарий в живом Foundry ещё требует проверки. Штатное применение урона SF2e не учитывает щиты модуля. Многие улучшения и способности НИП требуют решения ведущего. Отмена не является общей отменой любых изменений и не откатывает несколько документов атомарно. Условия эффектов и нестандартные перестановки инициативы могут потребовать ручной корректировки. Для изменения состояния нужен активный ведущий.

## Разработка

Нужны **Node.js 22.13+** и npm. Bash и отдельный архиватор не требуются.

```sh
npm ci
npm run format
npm run check
npm run build:release
```

В `dist/` появятся `module.json`, `module.zip`, контрольные суммы и заметки к выпуску. Для локальной проверки интерфейса:

```sh
npx playwright install chromium
npm run test:ui
```

Скомпилированные компендиумы, зависимости и архивы не коммитятся. Исходные данные находятся в `data/`; перед сборкой компендиумы создаются заново. GitHub Actions проверяет проект и собирает файлы релиза.
