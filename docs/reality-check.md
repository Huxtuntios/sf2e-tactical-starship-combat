# Reality Check after the combat-wizard merge

Assessment: 2026-11-12. Base: `f87c983a9cbafd4a9aff086bd416ed77bef9d6d5` (merged PR #14). Review branch: `review/reality-check-1.0`. Version remains `0.17.1-dev.13`; this is not a stable-release or live-compatibility certificate.

## Scope and architecture

The baseline contains 184 script modules, 88 unit-test files, two offline integration-test files, one architecture-test file, 19 templates and 22 declared packs. Review covered activation, document ownership, combat setup, Sensor Map, ship/crew/station services, attacks/checks/saves/damage, drones/mines/hazards, migrations, optional integrations, UI lifecycle, dependency installation, CI and packaging. Findings below were reproduced with production functions and Foundry document doubles; no licensed Foundry world was run.

- `scripts/main.mjs` registers settings, sheets, templates and API at initialization, then loads content and authoritative handlers at readiness. Active-GM migration/repair is distinct from client rendering.
- Module ship flags own SP, stations, crew, effects and tactical state. Hull HP belongs to `system.attributes.hp`. Sensor state belongs to Combat flags; private contacts and recovery intents belong to permission-checked GM-only Journals.
- UI intents go through authenticated native sockets to the active GM. Actor patch queues and Sensor Map operation queues protect different resources; neither constitutes a server transaction or a distributed lock.
- The existing wizard prepares and reviews a configuration before writing. World player Actors and deliberately reused retained copies remain eligible; independent copies and public-map membership are separate from instance-creation provenance.
- `TscApp`/`LiveMixin` manage rendering, delayed updates and close cleanup. No additional reproducible listener leak or wizard lifecycle defect was found in the inspected paths. This does not establish performance or lifecycle behavior in a live multi-client world.

## Documentation, provenance and data safety

Canonical technical/user documents live in `docs/`; the root contributor guide remains canonical. Duplicate copies and obsolete WIP reports are removed only after unique notes, limitations and historical evidence are retained in canonical documentation and release history. Existing guide section headings are preserved because generated page IDs depend on them. The limited Markdown-to-Journal converter and imported-world guide UUIDs still require live review.

AoN is a rules reference, not blanket evidence of bundled-content provenance: the repository also contains printed-text extraction/reconciliation tooling. Copyright, trademark and license notices are retained. The existing broad license grant and claims about reserved setting material require maintainer review, not an invented replacement legal grant. Inherited source notes are explicitly historical rather than assertions that a local Foundry installation or full-book review occurred during this audit.

No new gameplay/UI/marketing text or images were generated to disguise unknown authorship. Prepared content rights, human originals for AI-assisted wizard interface text, fluent Russian translation review, SVG rights and maintainer code understanding remain human gates in [release readiness](release-readiness.md).

No user world was opened or migrated. Source Actors/compendiums are not modified by the fixes; independent-copy recovery receipts are the only identity-specific flag intentionally removed during copy creation. No HP/SP/damage/critical-state Undo expansion, action/reaction budget spending, parallel wizard, forced dependency update or CI permission change is included.

## Remaining risks and release decision

- Multi-document Draft commits remain non-atomic. Guards prevent stale overwrites in the tested paths, but a document failure or concurrent conflict after another write succeeds can leave partial state. There is no generic rollback of damage and no automatic retry of a partially applied attack.
- Queues are local to the authoritative client. Active-GM change, external document updates, socket loss and deadlines do not provide exactly-once processing. Existing sender identity validation, GM authority and finite ACK/result deadlines are preserved.
- Four moderate development-only audit entries remain in the ESLint/minimatch chain; an upstream major-range mismatch prevents a routine compatible fix. Tooling is excluded from the installation ZIP; no unsafe downgrade or forced override was applied.
- Real install/upgrade, linked/synthetic Actors, multi-client authority/recovery, native rolls, optional integrations, guide rendering and representative performance remain untested here. Use the ordered [live acceptance gates](release-readiness.md#live-acceptance-gates).
- The release workflow still runs after publication and uses asset replacement; immutable-release draft preparation and human/policy gates must be satisfied separately. It was not modified or invoked.

**Decision: retain the pre-release version.** Prepare PR #2 and local artifacts for review only. Do not merge it, publish a stable tag or submit to the Foundry catalog until critical live/policy/provenance gates are satisfied.
