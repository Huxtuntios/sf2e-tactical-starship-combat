# Ручные проверки 0.17.1-dev.10 — НЕ ВЫПОЛНЕНЫ

Только в резервной копии тестового мира. Нужны Foundry v14.361+, подходящие SF2e/PF2e, этот модуль, отдельный клиент активного GM, второй GM и два отдельных аккаунта игроков. Для Toolbelt проверить подходящие по manifest версии; тесты dev.9 повторить с ним и без него. На момент сборки ни одна проверка ниже не выполнена в Foundry.

## Приватная карта — сначала проверить защиту, затем пользоваться

1. Проверьте права мира, журналов, папок, Actor, токенов, Compendium, настройки сторонних модулей и историю. Создайте тестовый NPC-корабль с доступом NONE всем игрокам, без токена, участника боя, старых сообщений и общей записи на карте. Создайте отдельно корабль игрока.
2. Откройте отдельные браузерные сеансы игроков. На стороне каждого сохраните исходные данные Combat, доступные документы, списки модуля и сообщения веб-сокета. В инструментах разработчика проверьте поступающие данные на имя, UUID, изображение и свойства тестового NPC. Обычное отсутствие DOM-элемента само по себе недостаточно.
3. Активный GM перетаскивает NPC в зону Sensor Map. У GM появится частный контакт «Необнаруженный», у обоих игроков — нет. Проверьте Combat flags и трафик сокета модуля: новые данные NPC в них не должны появиться. Проверьте журнал: нет папки, default NONE, нет предоставленных игрокам прав; исследуйте фактическую доступность документа и его flags каждому игроку через API и сетевые данные. **Если эти сведения доступны, не используйте функцию для секретов.**
4. Обновите обе страницы, закройте и откройте карту, передвиньте контакт и повторно перетащите Actor. Должна сохраняться единственная запись и прежнее состояние; игроки не должны получать её содержимое. Попытайтесь открыть контакт, искать его в меню/подсказках/HUD/карточках, проверить документы и сообщения API как игрок.
5. Временно дайте игроку LIMITED или добавьте корабль в Combatants до первой постановки: функция должна отказать. Уберите доступ и повторите. Проверьте другие способы раскрытия Actor и взаимодействие с другими модулями: модуль не может закрыть доступ, предоставленный другими механизмами.
6. Дважды проверьте границу сокета: неактивный GM и игрок не должны отправлять секретный UUID на канале модуля при попытке управления частным контактом. Активный GM — единственный редактор. Проверить смену активного GM, соединения, одновременные операции и доступность журнала на новом GM; очереди в отдельных клиентах не являются транзакцией.
7. Кнопкой раскрытия явно подтвердите идентификацию. Игроки получают имя, UUID и позицию и видят объект как identified. Это необратимое раскрытие. Промежуточные уровни здесь ещё не работают. После раскрытия проверьте существующие инструменты обнаружения. Проверить сбой при записи Combat и при очистке журнала, повтор — не должно возникнуть две общие записи. Если результаты расходятся, сохраните журнал и не повторяйте вслепую.
8. Старые общие контакты, корабли игроков и опасности: поведение как в dev.9; существующий контакт не должен автоматически сбрасываться. Убедитесь, что уже общедоступные сведения нельзя сделать секретными задним числом.

## Install Mine — только заметка для ведущего

1. Назначьте оператору консоль с одним Mine Deployment Shell и одним неразвёрнутым Pyrotechnics Drone. Установите фактический Mine Exocortex и проверьте известные модификации и мины у персонажа. Откройте вкладку станций.
2. Нажмите помощник установки, введите до четырёх разных обозначений мин и подходящие личные модификации, подтвердите требования. Проверьте заметку на дроне и карточку ведущему. Это не реальные записи инвентаря и не автоматическое применение.
3. Откажитесь от подтверждения; попробуйте пустые, дублирующиеся и более четырёх записей, неверный дрон, повтор ID, два дрона с одним ID, повторяющуюся станцию, отсутствие улучшения, смену оператора и развёрнутый дрон. Не должно быть частичного изменения или карточки.
4. Проверьте повтор одного запроса и конкурирующие операции; не должно быть повторной карточки. При обрыве соединения посмотрите фактическое состояние прежде чем повторять. После замены плана старый запрос не должен перезаписать новый.
5. Проверьте известные старые поля, квитанции, вместимость, Drone Block и Toolbelt: они должны сохраняться. Вручную контролируйте срок личного Modify и его эффекты; подготовленная запись не переносится на развёрнутую мину и не меняет формулу детонации.
