# Ручная проверка 0.17.1-dev.13

Этот список **не выполнялся в настоящем Foundry**. Проверяйте только на копии мира после резервного копирования, с Foundry v14 и поддерживаемой версией SF2e. Для проверки приватности нужны отдельные учётные записи GM и игроков. Мок и локальный Chromium не доказывают серверную изоляцию или поведение других модулей.

## Sensor Map

1. В активном космическом бою перетащите Hazard и Starship Actor из каталога на карту. Проверьте, что прежний drag-and-drop работает.
2. Откройте меню добавления объектов. Проверьте выбор Hazard и Starship Actor из мира, фильтр, тип NPC/Player и роль. Повторите из Actor-компендия: каждый выбор должен создать отдельный мировой Actor, а исходный документ и его данные должны остаться неизменными.
3. Как GM добавьте скрытый NPC Hazard и NPC Starship с состоянием undetected/hidden. Проверьте их сессии на отдельном игроке: имя, UUID, маркер и приватный журнал не должны раскрыться через карту, Combatants, chat, shared Combat flags или каталог Actor. Если обнаружен канал раскрытия, прекратите тест и не используйте механику для секретов.
4. Проверьте выбор Player Starship и Actors с доступом LIMITED/OWNER. Нельзя скрывать Actor, уже видимый игроку; выбранное состояние применяется без дополнительного подтверждения (`scripts/sensor/contact-service.mjs`). Скрытый Player Starship без прав игрока должен быть отклонён. У приватного контакта не должно быть публичного Combatant; публичный NPC-корабль или сложная опасность получают собственный Combatant (`scripts/sensor/actor-instance.mjs`).
5. Проверьте смену состояния/зоны приватного контакта и корректную очистку копии компендия при отменённом/неудачном добавлении.

## Станции из листа персонажа

1. Вне активного космического боя кнопки нет. Во время боя откройте лист персонажа — в меню листа должна быть команда управления станциями.
2. Игрок должен видеть только корабли боя, доступные ему по существующим правам. Проверьте текущее назначение, свободные станции и неисправные станции.
3. Займите свободную станцию; проверьте лист корабля и вторую клиентскую сессию. Покиньте станцию и проверьте обновление интерфейса. Назначение/освобождение должны идти через `Crew.claim`/`Crew.release`.
4. Двум игрокам одновременно попытайтесь занять одну станцию: только одна операция должна пройти, вторая должна увидеть занятое состояние. Проверьте повторное занятие и повторное освобождение. Владелец корабля/назначенный ведущий проверяет назначение, а связанный пользователь может освободить собственную станцию согласно правам `Crew`.
5. Не проверяйте автоматическое списание действий/реакций: его нет. Этот UI не вводит глобальное правило «одна станция на персонажа во всех кораблях».

## Drone Block, Deploy/Retrieve и мины

1. Создайте поддерживаемый нативный single-target Strike по Player Starship и нанесите урон через GM-кнопку карточки. На клиенте владельца целевого экипажа выберите один конкретный развёрнутый дрон. GM-подтверждение должно называть атаку, цель, выпавший урон, сопротивление и дрон.
2. Проверьте automatic: сопротивление применяется только к этому Strike через штатный damage pipeline. Проверьте manual: карта записывает использованный дрон, сопротивление и требование вручную разрешить именно этот урон; автоматически второй раз урон не применяется.
3. Для оператора 1-го уровня сопротивление равно 0, но Drone Block всё равно возвращает выбранный дрон и ставит 10-минутный запрет на Deployment. Для оператора 7-го уровня проверьте сопротивление 3. До истечения cooldown Deploy должен быть заблокирован; после истечения — доступен. Проверяйте world time.
4. Если установлен Drone Shield Protocol, используйте его отдельный ручной процесс. Проверьте GM-подтверждения, предел двух блоков на дрон, уничтожение экрана первым блоком и Fetch and Fix; автоматическая базовая ветка не должна обходить протокол.
5. Для Scramble Drone с записанным Intercept Munitions проверьте предупреждение. Drone Block сохраняет запись; явный Retrieve сбрасывает её в модуле. Правило не уточняет, считается ли автоматический возврат действием Retrieve Drone — окончательное решение оставьте GM.
6. Для Pyrotechnics Drone проверьте предупреждение, что хранимый запас и уже размещённые мины не меняются при Drone Block. Пока дрон возвращён, проверьте доступность Deploy, Retrieve и других зависящих от дрона операций. Не удаляйте и не переносите автоматически существующие записи мин; текст Tech Core не уточняет их судьбу при возврате/повторном развёртывании. Отдельно вручную проверьте Mine Stock, Deploy Starship Mine, отдельный Hazard Actor/контакт, движение и детонацию мин.
7. Отдельно проверьте отказ/таймаут reaction prompt, невозможность повтора одного Strike, GM-only подтверждение и сохранение состояния после перезагрузки. При неоднозначном/частично выполненном шаге сначала осмотрите Actor, карточку и журнал; не повторяйте вслепую.

## Совместимость и приватность

Проверьте реальные индексы Actor-компендиев, Foundry hooks AppV1/AppV2, права и сохранение изменений с установленными SF2e и PF2e/Anachronism. Повторите приватные сценарии с отдельными клиентами, после переподключения и при смене активного GM. Не считайте UI-скрытие, `api.privacyProbe()` или локальные тесты доказательством конфиденциальности.
