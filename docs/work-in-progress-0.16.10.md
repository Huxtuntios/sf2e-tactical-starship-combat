# 0.16.1-dev.10 — experimental, test worlds only

This is based on dev.9 and is not a release. Back up your world first; the archives of older versions are not changed. Action and reaction expenditure remains manual. Neither the existing drone work nor all previous tasks are complete.

## Boost Battle Station

The local Tech Core action data says: choose a battle station; its station actions gain +1 status to checks and damage rolls for one round. An indexed Archives of Nethys excerpt agrees, but direct AoN page loading returned HTTP 403 in this environment; this is not a complete rules or source verification. No additional restriction on an empty or malfunctioning _target_ station was invented. The selector identifies its occupant, status and existing boost. The source must be a working Generator helmed by the acting crew member, and the GM validates ownership, source and target again. To avoid an unanchored or indefinite effect, the current implementation requires an active starship combat, an operator combatant, and that operator's current turn. Exceptional/off-turn applications must be adjudicated manually by the GM; the module does not spend an action.

The bonus is saved on the target ship against the chosen station ID, not against an occupant. Repeating it refreshes the effect on that station rather than creating a second bonus; boosts on other stations stay separate. Ship sheet, Station HUD and Sensor Map dock display an indicator. The timing is anchored to the creator's next turn start, surviving ordinary save/reload when combat identities remain stable. Old unscoped or unanchored boost records are retained, not migrated or applied globally. Existing generic effects retain their old behavior. Changes to turn order, deletion/recreation of combatants, combat termination, and Undo require real-world manual verification.

Native station checks and PC weapon Strikes use the station-check modifier. PC weapon damage uses station-damage with SF2e's exposed Modifier / StatisticModifier when available; an existing module stacking fallback remains for environments where the API is missing. Damage bonuses on other station actions, including generic effect rolls and NPC/mixed damage, are not comprehensively integrated. The module does not claim all station-action damage is covered.

## Situational modifiers

After choosing a target for a single-target weapon Strike on the sheet or through the station runner, an optional dialog offers six per-roll entries. Leave rows blank to use none. Each entry has a name, optional source, nonzero integer (-100 to 100), status/circumstance/item/untyped type and attack/damage/both scope. The dialog lists known attack modifiers as a preview, not a full native character breakdown. The active GM must explicitly approve player-submitted entries before any roll; no active GM means the existing socket architecture cannot execute the request. Server-side validation does not prove that the game rules justify an entry; GM adjudication is still essential. Names and types are not persisted as a reusable library.

Attack modifiers are passed as system modifiers before a native attack check. The displayed SF2e attack card and MAP path remain in use; if the native check adapter is unavailable, the module's pre-existing fallback is not a native check. PC weapon damage modifiers are stacked with applicable station effects and folded into the formula before the roll and critical multiplier. They are not individually presented as native damage modifiers. Sheet attacks snapshot the damage formula at attack time; later changes before the separate damage roll are not re-evaluated. NPC/mixed-type damage modifier proposals are rejected, and standalone damage, AoE, spell attacks, persistent durations, reusable modifier lists and editing modifiers immediately before a delayed damage roll are not supported. Do not use this as a comprehensive replacement for SF2e's damage pipeline.

The validated native single-target attack path deduplicates event IDs as before. These mechanisms do not prove atomicity or failover safety across real GM changes. The existing active-GM ownership and targeted socket assumptions must be checked in the user's installation; no global chat suppression is introduced. No automatic damage is added to the deferred sheet roll path, while the station action retains the module's previous damage/application order.

## Rules and architecture evidence

- Local action: `data/actions/station-actions.json` (`boost-battle-station`) names the station target, bonus and one-round duration. The indexed official AoN Builder snippet agrees; the full AoN page was inaccessible (403). The local trait list includes `concentrate`, which was not verified against the full official entry and was not changed.
- SF2e 1.7.0 source tag exposes `game.pf2e.Modifier`, `game.pf2e.StatisticModifier`, and `Statistic.clone({ modifiers })`; the actual installed game/system behavior was not run. Mocks do not validate Foundry or SF2e compatibility.
- Previous `docs/drone-rules-matrix.md` and `docs/work-in-progress-0.16.9.md` still describe the boundaries of drone rules and earlier partial implementation. This update does not implement the remaining drone actions or three upgrades.
