# 0.16.1-dev.5 — incomplete experiment, test worlds only

Back up the world before testing. This is not a release. Earlier archives are not modified. Real Foundry v14 and live multiplayer were unavailable in the development environment; this build does not confirm Sensor Map performance, GM journal privacy, sockets, GM Override or Undo in a real world.

## Drone operations

Deploy Drone and Retrieve Drone are now station actions selecting one tracked drone. They check station occupancy, ownership and permission, the drone's state, station malfunction and cooldown. They change the state in the GM-authoritative ship queue; repeated same-state requests do not write, generate history or create a card. Undo is offered only for an isolated deployment/retrieval transition, subject to the existing state and combat conflict guards. Drone capacity and legacy-data protections remain. The station action displays its cost, but the module's existing action economy does not spend or enforce actions or reactions: the table must track them. No separate Combatant, initiative, hit points or AC is created.

A deployed Pyrotechnics Drone grants Deploy Starship Mine to its console; the operator chooses a specific qualifying drone. The authoritative handler stores a uniquely identified armed mine with owner, operator, drone, combat and zone, and tracks once-per-round usage per station. It requires an active starship combat and a ship placed on its Sensor Map, refuses another armed mine from the same drone in that zone, and is idempotent for an identical request ID. It does not detonate mines, apply damage or implement mine modifications. Mines are shown on the station; currently there is no UI for removing or resolving them. Mines tied to a different or unknown combat map block further placement by that drone until GM review; neither map coordinates nor records are silently discarded. Any raw-data repair requires a backup and GM. Mine placement is not Undoable. Multiple operators/consoles and concurrent map movement have not been validated in live Foundry; the station-based frequency interpretation and map-state synchronization require GM review.

Drone Block remains a manual reminder, not a working reaction: the existing weapon-card and damage flows do not yet reliably bind a particular hit, drone and attack-scoped resistance in one conflict-safe operation; per-drone 10-minute cooldown is not created. Detonate/Modify/Move Starship Mine, Repair Hull, Restore Functionality, Harry Sensors, Intercept Munitions and the effects of Drone Shield Protocol, Mine Deployment Shell and Pet Drone Shell remain unimplemented. Upgrade descriptions in the local catalogue are not the same as executing their effects. The engine's long-lived reaction Draft and separate actor/combat writes cannot guarantee atomic multi-document completion, and automatic Strike IWR cannot safely be substituted by subtracting an arbitrary amount. The installed SF2e data and accessible sources do not independently confirm every action cost, trait, duration, upgrade interaction and degree of success. Do not use the current implementation as full Drone Console rules automation.

## Other changes

The interactive ship attack-card path requests the native attack check without creating its separate roll message; the existing attack card contains the result. The damage message remains separate. Native SF2e / Foundry behavior still requires a live check, including reactions and roll visibility. Earlier dev.4 work shows damage type and explicitly recorded required proficiency, preserves native enrichers and supports explicitly typed damage; it does not infer a damage type from a source action, implement all interactive descriptions, or establish proficiency where source data does not contain it. Unknown is not a proficiency rank.

Full chat-source/no-op audit is not complete. Action cards and roll messages are distinct from the history announcement setting. The underlying history setting does not guarantee that every chat source follows Log Only / Important Only / All Changes. Previous automated tests cover the local catalogue's three standard frames, but not all imported/custom ships or live Foundry; the built-in exception must not suppress other compatibility errors. See earlier work-in-progress reports for prior changes.

A user observed freezes with an 8100 × 11700 Sensor Map background; very large images may freeze. Reducing dimensions is recommended. The observation is not proof of the rendering cause or a universal image-size threshold. No direct profiling in Foundry was possible in this environment.
