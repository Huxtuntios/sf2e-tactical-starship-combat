# 0.16.1-dev.2 — experimental, incomplete

This is not a release and does not complete the requested work. Back up the world and test on a copy. No Git commit, push or release was made. The manifest’s download URL refers to a release that has **not** been published; install the supplied ZIP manually in a test environment.

## Changes

- Player frame defaults are recognized only when the frame, original default station, compatible catalogue entry, lowest default variant and the old deterministic upgrade ID all match. They still occupy their station’s slot; only their level/capacity warnings are exempted. Other incompatible, unknown and level/capacity warnings remain. Custom/remapped stations or altered record IDs may still need GM review. No user records are rewritten for this recognition.
- New world setting **Chat announcements**: Log Only, Important Only (default), All Changes. These control optional state-change announcements; action cards, rolls, damage, sustain reminders and other existing intentional messages are not globally suppressed. Failed upgrade drops produce a local warning rather than a chat message. Repeat station claims do not announce changes. The actor write path skips equal normalized state when no extra update is required, but this is **not** a guarantee for every combat, socket or third-party path.
- New history snapshots are written to a bounded GM-only JournalEntry referenced by a hidden world setting. Existing trusted GM-whisper records remain in chat and remain readable and undoable; they are not deleted or automatically rewritten. The history store checks default ownership and rejects explicit non-GM access on use. Do not share it. A missing/shared/invalid store stops new history recording and warns the GM; the already-saved actor change is not rolled back. The store and its world setting must be backed up together. The journal path and privacy need testing in real Foundry before relying on them.
- Actor `patchStarship` read/validate/write is queued per ship on the active GM client. Automated concurrent mock tests cover specific upgrade/claim races; this is not a distributed transaction and does not establish replay protection or synchronization across changing GMs, all combat paths, or third-party writes.
- The existing manual Drone Block reminder now says half **your** level, in agreement with the action text already in the module. It does not implement deployment, individual drone state, cooldowns, or new drone actions.

## Sensor Map experiment (not a Foundry profile)

Local headless Chromium with GPU disabled, a synthetic 1200×800 page, the module stylesheet, 12 zones and 48 ship buttons; 4px blur and 100 measured iterations after 10 warm-up iterations. Compared replacing the viewport (including the background) with replacing only its zone subtree. Images were none, 512×512, and 4096×4096 generated PNGs. Two `requestAnimationFrame` callbacks were awaited after each DOM update. Median update time was 0.2–0.3 ms and median two-frame elapsed time 33.3 ms in each case. In the 512-pixel run, two-frame p95 was 50.1 ms when replacing the viewport versus 33.9 ms retaining it; the 4096-pixel run had p95 33.5 vs 33.7 ms. These are frame-scheduled timings, not isolated paint/compositing costs; GPU, browser scheduling, Foundry rendering, hardware, content and networking differ. They do not establish causation or demonstrate a fix. The current module still replaces the background with the zone section. Profile an actual Foundry session using Chromium Performance traces with and without background replacement and representative hardware/images before drawing conclusions.
