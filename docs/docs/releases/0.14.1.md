# 0.14.1 — Compatibility metadata and release integrity

- Explicit Foundry v14 and SF2e compatibility declarations.
- Packaging now rejects missing core/system compatibility declarations.
- The release workflow re-downloads and checks the uploaded assets: external and ZIP-root manifests must be identical and checksums must match.
- Fixes the stale-metadata distribution path: modifying `main/module.json` does not modify files attached to an older release. A new version is required to deliver the corrected files through the normal updater.
- No gameplay-rule changes and no widened support for Foundry v13 or PF2e worlds.

Requirements remain **Foundry 14.361+ within v14**, a world using **sf2e**, and **SF2e 1.6.0+**. The manifest declares v14 and the SF2e 1.6.1 patch target; this is release metadata, not a claim of newly executed live-world validation. Full multiplayer Foundry validation remains a manual step.

Publish a regular GitHub Release tagged **v0.14.1** after committing these sources to `main`. The Release workflow builds and attaches `module.json`, `module.zip` and `SHA256SUMS.txt` automatically. The permanent install URL is unchanged:

```text
https://github.com/Huxtuntios/sf2e-tactical-starship-combat/releases/latest/download/module.json
```

Back up your world before updating. Restart Foundry after installing; compare the installed module version and declarations, not only GitHub's source file.
