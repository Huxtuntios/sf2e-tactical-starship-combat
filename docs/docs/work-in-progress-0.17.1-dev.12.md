# 0.17.1-dev.12 — общий путь добавления объектов на карту датчиков и цикл мин

Экспериментальная неопубликованная сборка поверх dev.11. Релиз не публиковался, commit и push не выполнялись. **Реальные секреты ей не доверять:** приватность контактов в настоящем Foundry с несколькими клиентами не проверена (см. `MANUAL-TEST-0.17.1-dev.12-ru.md`).

## Что сделано

### 1. Добавление объектов на Sensor Map (ведущий)

- Кнопка «+» на панели карты открывает окно «Добавить объект на карту датчиков»: источник — опасность из мира, опасность из компендия или пользовательский контакт без Actor; зона; начальное состояние (`undetected`, `hidden`, `observed`, `identified`). Прежняя быстрая вставка объектов окружения (астероид, станция…) осталась отдельной кнопкой.
- Всё построено на приватном хранилище dev.10–dev.11 (`addPrivateContact`/`addPrivateCustom`/`changePrivateContact`); второй карты и второй механики контактов нет. `undetected` и `hidden` остаются только в закрытом журнале; `observed` публикует только анонимный маркер и требует подтверждения; `identified` публикует личность и тоже требует подтверждения. Отказ происходит до любых записей.
- Опасность из компендия не используется напрямую: для каждого размещения создаётся закрытая мировая копия (владение по умолчанию — нет доступа, флаг `contactImport`), чтобы у каждого экземпляра было своё состояние. Если размещение не удалось, свежесозданная копия удаляется.
- Опасность мира, уже видимая игрокам (LIMITED и выше), скрыть нельзя: допускается только подтверждённое размещение «опознан». Мины дронов в список не попадают.
- Для приватных контактов добавлен выбор зоны списком (в дополнение к ◀ ▶ и перетаскиванию); у публичных опасностей с известной личностью кнопка «Открыть лист» открывает существующий лист Hazard Actor (доступ определяют его права).

### 2. Мины

- **Install Mine** (Tech Core с. 184): подготовленные мины хранятся в `drone.mineStock` неразвёрнутого Pyrotechnics Drone, каждая — со своей подтверждённой модификацией (`installed.mods`, снимок названия). Модификации выбираются из известных модификаций оператора (`station.tscKnownMineMods`), которые подтверждает ведущий. До четырёх мин за действие; повтор безопасен (квитанции); модифицированную мину повторно модифицировать нельзя; класс механика проверяется по предмету класса, если он определяется, иначе подтверждает ведущий (переопределение — по решению ведущего). Личные модификации — непрозрачные записи: они не равны Smart/Targeting, не имеют эффектов и сроков. Старые заметки dev.10–dev.11 (`tscInstallMinePlan`) не трогаются и показываются как «старые заметки, не склад».
- **Deploy Starship Mine** (с. 192–193): существующие проверки не менялись. Теперь можно выбрать хранимую мину: она снимается со склада в том же изменении данных, получает свой id и сохраняет модификации в записи `drone.mines[]`. Обычная мина работает как в dev.11.
- **Контакт на карте**: запись мины остаётся источником истины. Её проекция — отдельный Hazard Actor (игроки — OBSERVER, папка «Starship mines») и публичный контакт `identified`, связанный полем `mineRef`. Это не Orbital Mine: у звёздной мины дрона другие числа, поэтому Actor создаётся для каждой мины, а не берётся из компендия. `syncMineContact` идемпотентна и находит уже созданные документы по флагам. Перемещение, закрытие (взорвана/убрана) существующими помощниками переносят или снимают контакт и помечают Actor. Сбой проекции не откатывает сохранённую мину; «Синхронизировать контакт» повторяет операцию.
- Контакт мины нельзя двигать, перетаскивать, менять тип и удалять напрямую (положение и существование задаёт запись мины); общая автоматизация опасностей (`onShipMoved`, `trigger`) его пропускает. Обнаружение править можно. Из окна карты доступны открытие листа корабля, помощник детонации и синхронизация.
- Развёртывание и установка необратимы (Undo не применим), поэтому расхождения с картой через Undo не возникает.

## Проверка Drone Block (код + характеризационные тесты `drone-block-audit-01712.test.mjs`)

Подтверждено чтением кода и тестами: сопротивление = ⌊уровень оператора / 2⌋; дрон возвращается и не может быть развёрнут ещё 10 минут мирового времени; предложение требует развёрнутого дрона версии 1 на консоли с оператором, не неисправной; Drone Shield Protocol его исключает; повтор по `strikeId` и повреждённые данные отклоняются без записи; прерванная реакция ничего не сохраняет (изменение только в черновике). Подсказка вызывается только для ударов, разрешаемых модулем (прямая Strike и карточка атаки), не для иных источников урона.
Наблюдения (поведение **не менялось**, нужны решения по тексту правил):

1. На уровне 1 сопротивление равно 0, но дрон всё равно возвращается и блокируется на 10 минут.
2. Drone Block возвращает дрон, но не сбрасывает записанное использование Intercept Munitions (`tscInterceptUsed`), как это делает обычное действие Retrieve. Допустимо, если Drone Block не считается Retrieve; иначе — расхождение.
3. Если Drone Block возвращает Pyrotechnics Drone с боевыми минами, мины остаются `armed`, но помощник не даёт двигать, модифицировать или взрывать их до повторного развёртывания дрона (10 минут). Сверить с напечатанным текстом Detonate.
4. Печатный текст Drone Block и Tech Core в этой сессии повторно не сверялся: поиск не вернул страницы SF2e на Archives of Nethys. Опора — каталог данных модуля (текст подтверждён вами по PDF в прежних сборках).

## Незавершено и ограничения

- **Настоящий Foundry не запускался.** Не проверены: серверная фильтрация закрытого журнала и копий компендия, права Actor, сетевые кадры, создание `Folder`/`Actor` типа hazard в SF2e 1.6.0 (данные опасности минимальны и опираются на значения системы по умолчанию), `pack.getIndex({fields:["type"]})`, диалоги DialogV2, смена активного GM, параллельные операции. Ручная проверка — `MANUAL-TEST-0.17.1-dev.12-ru.md`.
- **Браузерные фикстуры Chromium не запускались** (в среде сборки нет браузера); шаблоны проверены только компиляцией и рендером Handlebars в Node.
- Приватные контакты по-прежнему не участвуют в целеуказании и автоматизации опасностей до раскрытия. Операции из нескольких записей (журнал, Combat, Actor) не атомарны; очередь одного процесса не заменяет распределённую транзакцию.
- Ручное удаление Actor или контакта мины оставляет мину `armed` до следующей синхронизации. Уменьшение числа зон карты ниже зоны мины не пересчитывает запись мины.
- Новых миграций нет; существующие поля (`tscInstallMinePlan`, `tscMineModification`, `droneRepairReceipts` и др.) не удалялись и не переписывались.
