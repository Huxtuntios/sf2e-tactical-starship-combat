## Итог реализации и границы

**Частично:** GM подтверждает наличие классовой особенности Modify и выбирает Smart или Targeting для своей одной установленной мины. Нужны действующий бой, текущий ход однозначного оператора, однозначные ID станции/дрона/мины, одна запись корабля на карте, та же зона, развёрнутый Pyrotechnics Drone и активная мина текущего боя. Данные и права проверяются внутри очереди Actor. Снимок Actor и Combat проверяется перед сохранением. Одна активная модификация за раз — консервативное ограничение модуля; это не общий запрет правил на несколько модов.

`tscMineModification` хранит тип, оператора, бой, combatant, раунд создания/истечения и порядок combatants. До конца следующего хода оператора помощник считает модификацию активной; после окончания не применяет. Метаданные не удаляются автоматически. При смене порядка, потере combatant, другого боя, повреждённых данных и прочих сомнениях — отказ; GM разрешает вручную. При перемотке боя возможен повторный переход в кажущееся активное состояние, потому требуется проверка GM. Доступно только на текущем ходу оператора, а не произвольным способом вне боя.

План детонации проверяет срок: Smart выводит GM инструкцию исключить один корабль; Targeting показывает **ручную** формулу с текущим Int modifier, минимум 1, и намеренно не создаёт неполную ссылку на урон. Ни цели, ни исключение, ни спасброски, ни урон, ни взрыв автоматически не выполняются. Перемещение сохраняет ID и эти поля; существующий GM-инструмент продолжает требовать подтверждения Mobile Exocortex. Install Mine и его отличные от звездолётных модификации не реализованы. На печатной стр. 37 Tech Core личный Mine Exocortex описывает отдельные варианты Smart/Targeting с другими масштабами; их нельзя молча подставить вместо Install Mine или Modify Starship Mine.

Сохранён `tscModificationReceipts`: необязательный объект до 512 ID **на каждой модифицированной мине**, с проверкой payload. Тот же ID и те же параметры — no-op без повторной записи или карточки; другой payload с тем же ID отклоняется. Записи не вытесняются; заполненное или повреждённое хранилище требует GM. Новое нажатие генерирует новый ID; удаление receipts может снова допустить старые запросы. Никаких миграций, массовых обновлений или изменений других мин не выполняется. Существующие `droneRepairReceipts`, запись дронов, мин и старые поля не переписываются; к конкретной модифицированной мине добавляются два новых поля. Старые сохранения не проверены в настоящем Foundry — нужна резервная копия и пробный мир.

Очередь Actor существует только в одном процессе GM. Снимки уменьшают риск устаревших данных, но не дают атомарности с Combat, историей, чатом, внешними писателями или другим GM. При ошибке карточки после сохранения выводится предупреждение; не повторять без проверки. Карточка отправляется только GM, но это не делает flags Actor секретными: пользователи с доступом к кораблю могут прочитать поля мины. Даже если одна история/карточка записалась, другая может не записаться.

**Не реализованы:** Harry Sensors и окончания штатных условий (не найден подтверждённый штатный путь off-kilter для корабля); Intercept Munitions (нет проверенного общего pre-resolution интерфейса для всех путей Strike); Drone Shield Protocol/Fetch and Fix; Install Mine с личными Mine Exocortex mods; детонация, автоматическое воздействие и реакции на движение; Pet Drone Shell/Onboard Pet. Это пробелы реализации, а не доказательство, что они принципиально невозможны. GM разрешает вручную. Частичный Repair Hull dev.4 не менялся.

**Drone Block:** пользователь подтвердил printed source — половина уровня управляющего персонажа. Базовый код не изменялся; отдельный тест использует 9-й уровень персонажа и 2-й уровень корабля и ожидает сопротивление 4. Протокол по-прежнему блокирует автоматическую обработку, чтобы не применить базовое правило вместо улучшенного.
