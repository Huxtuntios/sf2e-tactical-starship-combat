## Included behavior

- Unified GM-controlled manual effects with explicit whole-ship, mechanic, station, action, weapon and crew scopes.
- Native crew condition/effect Items for supported recipients, stable operation IDs, partial rejection reporting and synchronized removal.
- Persistent-damage staging in the existing action Draft, strongest expected-value selection per damage type, native dice, durable receipts, explicit GM application and ordered recovery.
- One ordinary ship-turn interval, with one end-of-round fallback when the ship has no ordinary turn; crew turns and compromised hull-integrity turns do not add ticks.
- A combined Effect Manager and localized ApplicationV2 target dialog, retaining operational/destroyed controls and native valued conditions.
- Additive public API methods: `applyManualEffect`, `removeManualEffect`, `getEffectTargetCatalog`, `processPersistentDamage`, `applyPersistentDamage`, `recoverPersistentDamage`, `openEffectManager`.
- Preserved native-first targeting, hazard statistics/saves, plasma multi-target flow, Sensor Map range/detection/placement, chat-card outcomes and native condition management.
- Exact starship defense-map deletion/replacement, including custom keys and Foundry nested-object operator semantics.
- Independent map-only Sensor Map snapshots for repeated world and compendium placements, with no Actors Directory growth and isolated edits.
- Sensor Map arrow alignment plus persisted art rotation, horizontal mirror and heading-aware auto-mirror.
- GM-only Sensor Map ship/hazard action selector with distinct selection outline, zone/order labels, NPC/hazard actions and map-only Effects Manager.
- GM Combat Tracker true name/art for private contacts while player projections remain anonymous.
- Searchable localized Strike trait selector with custom-trait round-trip.
- Stored-card HTML sanitization plus working inline `@Damage` / `@Check` controls and GM-only private NPC action cards.
- Player Sensor Map pre-targeting with English `T` or pointer selection before an action, including target markers and matching detail refresh.
- Serialized map-only snapshot updates, retryable cleanup, cumulative hazard damage and guarded defense deletion.
- No general Undo or change-history UI. The existing narrow guarded Toolbelt per-application damage undo remains.

The module ID, pack names, document IDs and compatibility declarations are unchanged. New effect/receipt fields are optional and additive. `DATA_VERSION` increases from 2 to 3; the 2 → 3 migration fills a missing base `sensorRange` when a verified frame or size source is available and preserves existing values.

## Known limitations

- Live verification used the authenticated GM client and a separate connected `Player3` client for Sensor Map targeting, privacy and snapshot Open Sheet. A live PF2e + Anachronism session remains unexecuted.
- Toolbelt persistent-card routing was verified through the live service/card path, but Workbench, HoloDock, Aztec and Causodes still have source/mock/fixture evidence only for this integration.
- Two initial fixture scripts failed before scenario execution because the hazard pack index is a `Collection` and native `clumsy` requires a value. Both fixtures were corrected and the final 24/24 matrix passed; these intermediate errors are not production runtime failures.
- State-changing effect and persistent-damage operations require the authenticated active GM. Unsupported native conditions/mechanics and weapon defenses reject rather than guessing.
- Action/reaction economy is not tracked. Native system damage buttons still bypass module Shield Points outside the module's guarded damage routes.
- The post-1.5.0 backlog T-045–T-051 and PR #26 review fixes T-053–T-065 have passed their live Foundry checks; this preparation remains untagged and unpublished.

## Installation

### Verified local artifact

1. Back up the target world and disable the currently installed module copy.
2. Use the locally built `dist/module.zip`.
3. Extract it into `Data/modules/sf2e-tactical-starship-combat/` so that `module.json` is directly inside that directory.
4. Enable **SF2e Tactical Starship Combat**, reload the world and verify the loaded version is `1.5.0`.
5. The v1.5.0 GM checklist, separate player-client checks and post-1.5.0 backlog live checks below have passed; review the open PR #26 before campaign-wide rollout.

GitHub automatic source-code archives are development sources, not installable module packages.
